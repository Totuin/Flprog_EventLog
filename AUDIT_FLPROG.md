# Ревизия Flprog_EventLog 1.0.1 — технический протокол

Источник: `libraries.zip` от 10.11.2026; код `Flprog_EventLog 1.0.0`. Дата ревизии: 12.11.2026.

## Проверенные исправления

- Исправлена сортировка и нормализация весов: в 1.0.0 `resetWeight()` начинал с `_virtualIndexes[_recordsSize]` и обращался к несуществующей записи. Переполнение `uint16_t` теперь контролируется, сортировка повторно обновляется после удаления или полной очистки.
- Добавлена обработка нулевого числа записей; предотвращено разыменование за пределами `getRecordWithVirtualIndex` и `getUsedRecordsSize`.
- Реализовано управление памятью динамических полей и таблиц; введены виртуальные деструкторы, инициализация указателей нулями, запрет копирования владельца; повторная смена типа поля освобождает предыдущий объект.
- RAM `setLongField()` теперь создаёт `FlprogEventLogLongValueField` (32 бита); до исправления создавалось `IntValueField` (16 бит).
- EEPROM `setWeightAddress()` больше не вызывает `setWeight(0)` и не стирает журнал при привязке адресов.
- `setEEprom()` выполняет предварительный расчёт всей разметки в `uint32_t`, не начинает привязку при ошибке, не допускает стартового адреса 0 и переполнения возвращаемого 16-битного end-адреса.
- Отвергаются ID событий >255, поскольку исторический формат EEPROM и абстрактная запись сохраняют ID в uint8_t.
- Исправлены переносимые пути include, оба примера (размер EEPROM и частота регистрации), добавлены русские комментарии и документация.

## Сохранено

- Имена публичных функций, классов, сигнатуры методов; историческое `setEEprom`, `FlprogEventLogUnLongteValueField` не переименовывались.
- Структура EEPROM: битовые bool, затем для каждой записи ID (1), вес (2), поля остальных типов (1/2/4 байта); никакой автоматической миграции данных.
- Исходники `Flprog_EEPROM`, RT_HW, FLProg_Network и всех остальных библиотек не изменены.
- `keywords.txt`: 74 записи (21 KEYWORD1, 53 KEYWORD2), дубликатов и ошибок разметки нет. Оригинальный файл сохранён.

## Автономные проверки

- C++11 GCC, `-Wall -Wextra -Werror -pedantic`, ASan и UBSan: основная модель (RAM, EEPROM, нулевые размеры, длинные серии записей, переполнение, удаление, восстановление) — PASS.
- C++11 с настоящим `flprogEEPROM.cpp` и API из `Flprog_EEPROM 1.0.1` (на host Arduino-заглушке): повторное создание журнала и чтение полей `bool`, `byte`, `int16`, `int32`, `uint32`, `time` — PASS.
- Синтаксис примеров с имитациями Serial/Arduino/EEPROM — проверяется отдельным скриптом.

## Ограничения

- Нет испытаний с Arduino Core и реальной EEPROM; необходима пользовательская компиляция и по возможности тест физического хранения после перезагрузки питания.
- Размер фактической EEPROM неизвестен классу журнала: вызывающий код обязан проверять возвращённый адрес против выделенного объёма.
- Переименование полей/изменение их типов без миграции несовместимо со старой разметкой; при потере питания между отдельными записями EEPROM целостность группы полей не гарантируется.
- При повторном использовании записи незаполненные поля сохраняют прошлое значение: следует записывать все поля каждого нового события.
- Динамическое выделение и сортировка O(N²) нежелательны для очень больших журналов и слабых AVR.

Статус: кандидат 1.0.1 — ожидает подтверждения компиляции FLProg.
